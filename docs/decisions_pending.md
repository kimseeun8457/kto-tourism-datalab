# 데이터 확인 후 확정할 것

> 범위 조정(2026 경진대회 출품작, 연휴 유형별 분석 중심)에 따라 잠재지역 발굴 관련
> 항목(잠재지역 평가 변수/스코어 가중치/최종 분석지역 수)은 범위에서 제외되어 삭제함.
> 관련 내용은 README.md 참고.

## STEP 1: 공휴일+주말 캘린더 구축 및 유형화

- 연휴 유형 5종(순수주말형/단일휴일형/주말연계형/징검다리형/장기연휴형) 분류 기준
  - 예: 토/일 단독 → 순수주말형, 평일 공휴일 단독(전후 주말과 미연결) → 단일휴일형,
    공휴일이 주말과 바로 붙은 경우 → 주말연계형, 공휴일 사이 평일 1일이 낀 경우
    (대체휴무 여부 포함) → 징검다리형, 3일 이상 연속 → 장기연휴형 — 구체적인
    일수/붙는 기준 확정 필요
  - 대체공휴일을 원 공휴일과 같은 연휴 인스턴스로 묶을지, 별도로 볼지

## STEP 2: 인스턴스 단위 Holiday Lift 계산

- 평시 비교기간: **동일 요일 ±4주 로컬 기준선**으로 확정
- 기준선 계산 시 "다른 공휴일과 겹치는 날짜" 제외 기준 — 겹침 판정 범위(해당 공휴일
  자체만 제외할지, 전후 주말까지 포함해 제외할지)
- 연도별 반복성 검증 시 평균/표준편차 외 이상치(outlier) 처리 기준

## STEP 3~4: 지역별 비교 및 유형화 (시간 여유 시)

- Holiday Lift 비교 시 수도권 등 특정 지역 포함/제외 여부
- (STEP 4 진행 시) 관광핵심형/휴일특수형/일상관광형/저반응형 4분면 분류 기준
  (Holiday Lift 값과 평시 방문규모의 임계값을 각각 어떻게 설정할지)

## STEP 5: 정책 제안

- 연휴 유형별 정책 제안의 구체적인 산출물 형식(유형별 대표 지역 사례 vs 일반화된 제언)

## API 데이터 존재 여부 확인 필요 (notebooks/step0_api_test.ipynb 실행 후 반영)

- 관광 다양성(AreaTarDivService), 관광 자원 수요(AreaTarResDemService), 관광 수요 강도
  (AreaTarDemDsService) 3개 API는 2024년(baseYm=202401) 데이터 존재 여부가 미확인 상태.
- 위 3개 중 2024년 데이터가 없는 API가 있다면, 해당 API의 활용 범위(분석 시작 연도,
  대체 지표/데이터 소스 필요 여부)를 재조정해야 함.
- 노트북 실행 결과(✅/❌)를 확인한 뒤 이 섹션을 구체적인 결론으로 갱신할 것.
